# Supabase 開発の【4つの絶対ルール】

今回の重大なシステムフリーズを教訓に制定された、当プロジェクトにおける4つの絶対ルールです。今後のコード提案や修正において必ず遵守してください。

1. **【select(*)の禁止】**
   Supabaseへのクエリでは `select('*')` を一切使用せず、必ず必要なカラムを明示的に指定（例：`select('id, title...')`）すること。これにより、DB側のカラム削除時にPostgRESTのスキーマキャッシュ不整合による内部エラー（500/400）で通信全体がハングアップする事故を防止します。

2. **【クライアントの一本化】**
   `createClient` は `src/supabaseClient.js` でのみ1回だけ実行し、各コンポーネントはそれをインポートして使用すること。
   ※複数インスタンス化すると、ブラウザ内で Navigator LockManager のロック競合によるデッドロック（10秒タイムアウト）を引き起こすため。

3. **【DBマイグレーションの順序】**
   DBのカラムを削除・変更する際は、**必ず「フロントエンド側のクエリから該当カラムの指定を削除・デプロイ」した後に**、DB側の変更を行うこと。

4. **【隠し通信の禁止】**
   `index.html` への raw fetch 等の直書き（事前読み込み等）は行わず、データの取得は適切なエラーハンドリング（try-catch）が効くReactのライフサイクル内で行うこと。
   ※エラー発生時にコンソールで検知しづらく、さらにAPIゲートウェイの詰まりによって後続のReact内の全通信（WebSocket等含む）がブロックされる原因となるため。
